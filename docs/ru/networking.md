# Управление сетью

[English](../en/networking.md) · [Документация](../README.md)

Сейчас Pinology предоставляет два режима доступа через NAT на Mac и Linux ARM64.
Ни один из них не выдаёт DSM отдельный адрес от роутера.

| Режим | Доступ | DHCP-адрес роутера для DSM |
| --- | --- | --- |
| `--network local` (по умолчанию) | Только с хоста или через SSH-туннель | Нет |
| `--network host --bind-address HOST_IPV4` | Выбранные порты на IPv4-адресе хоста | Нет |
| Bridge / прямое подключение к LAN | Пока не реализовано в публичном CLI | Нужно для отдельного адреса от роутера |

Здесь `host` означает **использование адреса хоста**, а не Docker `--network host`.
Контейнер Linux сохраняет отдельное сетевое пространство. Pinology не меняет
bridge, интерфейсы хоста, роутер, firewall или настройки VPN. Docker управляет
своими обычными правилами публикации портов; см. [документацию Docker](https://docs.docker.com/engine/network/port-publishing/).

## Доступ через адрес Mac/Pi

Найдите IPv4-адрес хоста в доверенной локальной сети: в настройках сети или списке
устройств роутера. Это должен быть адрес **этого хоста**, а не свободный адрес,
который хочется назначить DSM. Подставьте его вместо `HOST_IPV4`:

```sh
./pinology start instances/nas --network host --bind-address HOST_IPV4 \
  --port 15504 --https-port 15505 --smb-port 14445
```

Добавьте `--experimental-ds423` и/или `--experimental-gicv2`, если они нужны для
вашей модели/хоста. С другого устройства локальной сети открывайте:

- Веб-интерфейс: `https://HOST_IPV4:15505/` → TCP 5001 гостя.
- HTTP/установщик: `http://HOST_IPV4:15504/` → TCP 5000 гостя.
- SMB: `smb://HOST_IPV4:14445/SHARE` → TCP 445 гостя; сначала создайте общую папку в DSM.

`--https-port` необязателен и не настраивает TLS внутри DSM. HTTPS заработает,
когда DSM включит соответствующую службу; установщик может предоставлять только
HTTP. Используйте доверенный сертификат и проверяйте его принадлежность, а не
игнорируйте предупреждения вслепую. Для ввода паролей в LAN предпочтителен HTTPS.
Если автоматическое перенаправление DSM ведёт на гостевой порт 5001, откройте
явный HTTPS-адрес с проброшенным портом выше. SMB-клиенты без поддержки указания
нестандартного порта напрямую к такому пробросу не подключатся.

Порты хоста должны быть разными, свободными и находиться в диапазоне 1024..65535.
Root и privileged-контейнер для этого не нужны. Публикуются только выбранные
HTTP/SMB/необязательный HTTPS, не все порты пакетов; broadcast-discovery не
пробрасывается. Не назначайте адрес хоста интерфейсу внутри DSM: оставьте гостевую
NAT-сеть без изменений. Для постоянного URL закрепите DHCP-адрес **хоста** на
роутере. При смене этого адреса штатно выключите DSM и перезапустите с новым
bind-адресом: конкретный адрес не подменяется прослушиванием всех интерфейсов.

Чтобы явно слушать все IPv4-интерфейсы, укажите `--network host --bind-address
0.0.0.0`. Это включает VPN и другие доступные интерфейсы, а не только LAN.
Подключайтесь по настоящему IP хоста, не по `0.0.0.0`. Предпочтителен конкретный
LAN-адрес. Не открывайте порты в интернет и не публикуйте ненастроенный установщик
DSM в недоверенную сеть. Первичную настройку лучше выполнить в локальном режиме.

## Смена режима и возврат к локальному доступу

Выключите систему из DSM и дождитесь завершения оболочки/контейнера. Запустите
**тот же** экземпляр с нужными параметрами; не повторяйте `init` и не меняйте
диск/flash. Параметры относятся к текущему запуску и не меняют режим по умолчанию.

```sh
./pinology start instances/nas --network local
```

Локальный режим слушает только `127.0.0.1`; `--bind-address` не может незаметно
расширить доступ. `./pinology status` и авторизованный `./pinology stop` продолжают
учитывать выбранный адрес, а на Linux работают внутри сети контейнера.
Подробнее — в [руководстве по запуску](usage.md).

## Старые сборки и диагностика

Для существующего Mac-комплекта нужен новый runtime: см. [обновление Pinology](updates.md#обновление-pinology).
Docker-образ тоже пересоберите для использования актуального runtime. DSM заново
устанавливать не требуется. Ошибка bind обычно означает, что адрес не принадлежит
хосту или порт занят; изучите вывод оболочки и журналы QEMU.

Если с хоста доступ есть, а с другого устройства нет, проверьте адрес, firewall,
изоляцию Wi-Fi-клиентов, VLAN-маршрутизацию и публикацию Docker-портов. Pinology не
открывает firewall автоматически. Успешный локальный запрос не доказывает доступ
из LAN. Для отдельного DHCP-адреса от роутера потребуется отдельный bridge/direct-LAN
backend с учётом прав и адаптеров хоста; текущая возможность его не реализует.
