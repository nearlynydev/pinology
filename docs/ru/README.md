# Pinology

[English](../../README.md) · [Документация](../README.md)

Запуск ARM DSM на Apple Silicon и Linux ARM64 с собственной моделью платы в QEMU.
Pinology предоставляет проверенные профили прошивки, виртуальный диск, нативное
ускорение на Mac и доставку через Docker на Linux.

**Экспериментальный исследовательский проект, не NAS для важных данных.** Он не
связан с Synology и не включает DSM, лицензию на DSM или доступ к облачным сервисам.
Используйте тестовые данные и независимые резервные копии.

## Что работает и что экспериментально

| Платформа или возможность | Статус |
| --- | --- |
| Apple Silicon macOS | Нативный QEMU с HVF; рекомендуемый путь на Mac |
| Linux ARM64 | QEMU в Docker с явным доступом к KVM |
| CM4 / Raspberry Pi 4 | Экспериментальный KVM с GICv2; исследовательская сборка проверена на CM4 |
| Raspberry Pi 5 | Не проверена |
| DS223 | Профиль по умолчанию |
| DS423 | Выбирается при создании; запуск требует экспериментального флага |
| CPU / RAM / диск | Четыре vCPU, 2 ГиБ RAM, один виртуальный диск; без проброса дисков хоста |
| NPU / физический датчик потребления | Недоступны |

Исследовательская сборка прошла реальные загрузки Mac HVF и CM4 KVM, SMB с контролем
хешей и проверки штатного reboot. Это не сертификация всех пакетов и каждой сборки
новой публичной оболочки. Подробнее — [совместимость](architecture.md).

## Быстрый старт

Проект распространяется **в исходниках**. Сначала установите
[зависимости хоста](installation.md), затем из корня репозитория выполните:

```sh
./pinology doctor
./pinology build
mkdir -p instances
./pinology init instances/nas --model DS223 --disk-size 32G
./pinology start instances/nas
```

На CM4/Pi 4 с Linux замените последнюю команду на
`./pinology start instances/nas --experimental-gicv2`.
Запуск остаётся в текущем терминале. Откройте <http://127.0.0.1:5000/> на хосте
или используйте [SSH-туннель](troubleshooting.md). Пройдите мастер установки DSM:
инициализация сама по себе не создаёт установленный NAS и учётную запись администратора.

`init` загружает с серверов Synology соответствующий модели DSM 7.2.2-72806 PAT
и проверяет закреплённый SHA-256. На Mac автоматическое извлечение PAT использует
закреплённый Docker-helper, но сам гость работает нативно с HVF. Альтернатива —
собственный подходящий PAT и уже извлечённые файлы. Прошивки и готовый эмулятор
здесь не распространяются.

Для DS423 укажите `--model DS423` при создании **нового** экземпляра и
`--experimental-ds423` при `start`. Это не преобразование существующей установки.

## Безопасная эксплуатация

Если порт хоста занят (на macOS 5000 может занимать AirPlay), переопределите только
его: `./pinology start instances/nas --port 15504`, затем открывайте порт 15504.

Для доступа из LAN: `./pinology start instances/nas --network host`.
Прослушивается `0.0.0.0` с родными портами 5000 (HTTP), 5001 (HTTPS), 445 (SMB).
Переопределение: `--port`, `--https-port`, `--smb-port`; необязательное ограничение
интерфейса: `--bind-address`.
См. [управление сетью](networking.md). Это порты на адресе хоста, а не отдельный
DHCP-адрес DSM; bridge пока не реализован.

Выключите систему из DSM и дождитесь выхода оболочки перед копированием или
переносом экземпляра. После этого создайте холодный checkpoint:

```sh
./pinology backup instances/nas instances/nas-checkpoint
```

Не подключайте экземпляр к двум VM. Не публикуйте тестовую систему в интернете.
Порты хоста по умолчанию доступны только через loopback; автозапуск хоста не
устанавливается. Обновления DSM ограничены разрешёнными загрузочными профилями:
поддержка произвольных будущих версий не гарантируется. См. [обновление DSM и
Pinology](updates.md): версии, установка по сети/вручную, проверки и откат.
