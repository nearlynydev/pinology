# Запуск и настройки

Публичный `./pinology` выбирает нативный HVF на Apple Silicon и Docker с KVM на
Linux ARM64. Он намеренно предоставляет меньше настроек, чем исследовательский
runtime. Синтаксис команд: `./pinology COMMAND --help`.

## Команды

| Команда | Назначение |
| --- | --- |
| `doctor` | Базовые проверки хоста; не полноценный тест сборки или VM |
| `build` | Локальная сборка Mac-комплекта или Linux Docker-образа |
| `init PATH` | Создание закреплённых установочных файлов, flash и виртуального диска |
| `start PATH` | Запуск в текущем терминале; HTTP/SMB по умолчанию на loopback |
| `status PATH` | Состояние экземпляра; не полный аудит служб DSM |
| `stop PATH --credentials FILE` | Авторизованная команда выключения DSM и ожидание |
| `backup PATH NEW_DESTINATION` | Проверенный холодный checkpoint; источник должен быть выключен |
| `menu` | Терминальное меню на Mac; нужен собранный комплект |

`init` принимает `--model DS223|DS423`, `--disk-size 32G`, необязательные
`--serial`, `--pat` и `--artifacts`. Размер задаётся целым числом с M/G/T
(двоичные единицы), от 8G до 16T. Публичный сценарий создаёт sparse qcow2:
больший размер не резервирует столько же физического места и не увеличивает
уже существующий диск. Следите за свободным местом на хосте.

`start` принимает `--port` (по умолчанию 5000), `--smb-port` (445),
`--https-port` (5001), `--network local|host`, `--bind-address`,
`--experimental-ds423` и `--experimental-gicv2`. Порты хоста должны быть разными,
свободными и в диапазоне 1..65535; ограничения ОС на низкие порты сохраняются.
GICv2 включается явно только на Linux;
DS423 требует своего флага независимо от хоста.

```sh
./pinology start instances/nas --port 5000 --smb-port 445
# В другом терминале:
./pinology status instances/nas
```

На Mac status показывает состояние VM через QMP. На Linux запускает проверку
готовности в сетевом пространстве проверенного работающего контейнера.
Запущенная VM не обязательно имеет готовый API; готовый API не означает
исправность всех пакетов DSM.

## Сеть и перезапуск

Используется user-mode NAT. По умолчанию HTTP и SMB доступны на 127.0.0.1 хоста.
Для доступа из LAN укажите `--network host`: по умолчанию слушается `0.0.0.0`.
`--bind-address` — необязательное ограничение; см. [управление сетью](networking.md).
Автоматического bridge, отдельного LAN IP и проброса discovery-рассылок нет.
Внутренний wildcard-адрес Docker ограничен приватной сетью контейнера.
Не переводите контейнер на host networking.

Перед подключением к `smb://127.0.0.1:445/SHARE` создайте общую папку в DSM.
Используйте собственные данные DSM. В локальном режиме для удалённого хоста пробросьте сервисы:

```sh
ssh -N -L 5000:127.0.0.1:5000 -L 14445:127.0.0.1:445 user@pi-host
```

В этом примере SMB на клиенте доступен по `smb://127.0.0.1:14445/SHARE`.

Оболочка включает постоянную flash, локальный serial-сокет и ограниченный
автоматический возврат после reboot. Повторный запуск разрешён только после
подтверждённого guest reset; poweroff, авария и неизвестная причина оставляют VM
выключенной. Допускаются три перезапуска за пять минут, следующий reset
останавливает цикл. Flash проверяется каждый раз. Автозапуск хоста и автоматический
рестарт после аварии не устанавливаются.

## Безопасное выключение

Проще всего выбрать **выключение в DSM**, затем дождаться выхода оболочки или
контейнера. Закрытие терминала, Ctrl-C, завершение QEMU и `docker stop` без
настроенного выключения гостя не эквивалентны этой операции.

Для публичной команды stop создайте в редакторе приватный JSON-файл ровно с двумя
полями `account` и `password`, содержащими данные администратора DSM. Не добавляйте
его в Git. Ограничьте доступ и передайте только путь:

```sh
chmod 600 /absolute/private-shutdown.json
./pinology stop instances/nas --credentials /absolute/private-shutdown.json
```

Команда авторизуется локально и вызывает штатное выключение DSM. Она ждёт
освобождения блокировок VM/оболочки и не обрывает питание при ошибке. При проблемах
авторизации, сети или выключения изучите результат и завершите операцию из DSM.
Собственный тайм-аут принудительной остановки Docker остаётся отдельным риском.

## Checkpoint и восстановление

После выключения выберите несуществующий каталог внутри существующего родителя:

```sh
./pinology backup instances/nas instances/nas-checkpoint
# Восстановление в НОВЫЙ экземпляр, без перезаписи старого:
./pinology backup instances/nas-checkpoint instances/nas-restored
./pinology start instances/nas-restored
```

Checkpoint включает диск, flash, манифест и исходные загрузочные файлы. Инструмент
отказывается копировать работающую VM, проверяет qcow2 и хеши скопированных данных.
Журналы runtime не включаются. Copy-on-write копия защищает от ошибок гостя, но не
от отказа диска хоста; держите независимую резервную копию на другом носителе.

Перед обновлением сделайте checkpoint выключенной системы, затем запустите её.
Используйте только обновление, итоговый профиль которого для вашей модели разрешён
текущими исходниками. Не включайте бесконтрольные обновления на произвольную прошивку.
Полный порядок, список версий и откат описаны в [инструкции обновления](updates.md).

## Идентичность и дополнительные настройки

Необязательный серийный номер задаётся только при `init`. Новый манифест закрепляет
fingerprint идентичности, в том числе отсутствующей. Неожиданное изменение позже
останавливает загрузку; оболочка не генерирует и не восстанавливает номер сама.
Копируйте flash вместе с манифестом. Наличие номера не подтверждает право на облако.

Публичная CLI **очищает унаследованные настройки исследовательского runtime**.
Она не принимает `--config`, не читает `settings.env` автоматически и не передаёт
настройки вроде `ACCEL`, `SERIAL`, `DISK_FMT`, `MAC` и `USER_PORTS`.
Не считайте, что эти переменные меняют поведение `./pinology start`.

Разработчики могут изучить отдельный низкоуровневый
[пример настроек](../../kernel/stock-board/settings.env.example) и
[парсер](../../kernel/stock-board/settings.py) с дополнительными параметрами
диска/сети. При его использовании настройка ускорителя, mounts, портов и выключения
остаётся на пользователе: это не ещё один публичный контракт CLI. CPU/RAM остаются
фиксированными: четыре vCPU и 2 ГиБ.
