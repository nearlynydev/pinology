# Установка

Соберите проект локально, создайте новый экземпляр и пройдите штатный мастер DSM.
Публичный интерфейс — `./pinology`; команды выполняются из корня репозитория.
Используйте тестовое хранилище. Существующие каталоги экземпляров не перезаписываются.

## Apple Silicon macOS

Нужны ARM64-терминал, Python 3.11 или новее, Xcode/Command Line Tools 16.2+
(macOS SDK 15.2 или новее) и Homebrew. В старых SDK нет заголовков Hypervisor,
нужных закреплённой версии QEMU; `doctor` и `build` проверяют SDK до компиляции.
Установите зависимости самостоятельно: оболочка не меняет системные пакеты.

```sh
xcode-select --install
brew install python meson ninja pkg-config glib dtc qemu openssl@3 gpatch
./pinology doctor
./pinology build
```

Если Command Line Tools уже установлены, пропустите `xcode-select --install`.
QEMU из Homebrew предоставляет `qemu-img`; гость использует эмулятор с патчами
проекта, а не обычный Homebrew QEMU. Сборка загружает закреплённые по хешам
исходники QEMU/libslirp, компилирует их и создаёт `dist/pinology-macos`.
Готовый каталог не перезаписывается: сохраните или перенесите его перед следующей
сборкой. Локальная ad-hoc подпись разрешает HVF; это не нотарифицированное приложение
и не опубликованный бинарный релиз.

Для автоматического извлечения PAT также нужен установленный и запущенный Docker.
На этом этапе он лишь вспомогательный инструмент: DSM на Mac работает нативно
с HVF. Чтобы обойтись без helper, передайте подходящий PAT и уже извлечённые файлы.

## Linux ARM64 и Raspberry Pi

Нужны 64-битные Linux и userspace, Python 3.11+, рабочий Docker и доступный
`/dev/kvm`. Предусмотрите 2 ГиБ для гостя **плюс** память эмулятора, Docker,
ОС и существующих задач. Описанный сценарий не требует замены ядра хоста или
privileged-контейнера.

```sh
./pinology doctor
./pinology build
```

Команда собирает локальный образ `pinology:local` из исходников, а не загружает
готовый релиз Pinology. Зависимости сборки и экстрактор PAT получают внутри сборки
образа. Установка Docker/KVM пакетным менеджером зависит от ОС и не выполняется
Pinology автоматически.

Проверенная исследовательская сборка CM4 использует KVM с `--experimental-gicv2`.
Это также предполагаемый путь для Pi 4, но не гарантия для любой платы и ОС.
Pi 5 не проверена. Проверяйте доступ к `/dev/kvm` и наличие контроллера памяти:
запрошенные ограничения Docker не обязательно действуют.

## Создание и установка

```sh
mkdir -p instances
./pinology init instances/nas --model DS223 --disk-size 32G
./pinology start instances/nas
```

На CM4/Pi 4 используйте `./pinology start instances/nas --experimental-gicv2`.
Инициализация загружает официальный закреплённый DSM 7.2.2-72806 PAT, проверяет
хеш, извлекает загрузочные файлы модели и создаёт один новый диск и flash.
Соседний каталог `instances/nas.media` сохраняет установочные файлы. Оба каталога
должны быть новыми; неудачные попытки остаются для диагностики.

Откройте <http://127.0.0.1:5000/>. Для удалённого хоста используйте
[SSH-туннель](troubleshooting.md). Пройдите мастер DSM и задайте собственные данные
администратора. Если потребуется файл установки, укажите тот же проверенный PAT
из `instances/nas.media/boot.pat`. Общей учётной записи по умолчанию нет.

Публичный `start` теперь использует порты 5000/5001/445. Если порт занят другой
службой (например, AirPlay на macOS занимает 5000), переопределите его через
`--port`, `--https-port` или `--smb-port`, не останавливая службу автоматически.
Подробнее — [управление сетью](networking.md).

Для собственных проверенных файлов вместо загрузки и извлечения:

```sh
./pinology init instances/offline-nas --model DS223 \
  --pat /absolute/DSM_DS223_72806.pat --artifacts /absolute/extracted-pat
```

Это исключает загрузку PAT и helper извлечения, но не делает первоначальную сборку
эмулятора офлайн. Произвольная версия DSM или PAT другой модели не пройдут проверку.
Получайте и используйте прошивку с соблюдением применимых условий Synology.

## DS423 и идентичность

DS423 создаётся отдельно с `--model DS423` и запускается с
`--experimental-ds423`. На CM4/Pi 4 добавьте также `--experimental-gicv2`.
Не используйте диск установленной DS223. Несмотря на выбор модели при создании,
DS423 остаётся экспериментальной.

Необязательный `init --serial YOUR_SERIAL` записывает указанную пользователем
идентичность в новую flash. Без него номер остаётся незаданным, ничего не
генерируется. Допустимы заглавные ASCII-буквы и цифры; значение с контрольной
суммой должно помещаться в поле производителя. Номер не даёт лицензии или доступа
к облаку. Аргумент может попасть в историю shell и список процессов; штатный журнал
загрузки тоже может содержать номер. Храните экземпляр, установочные файлы и логи
приватно. Загрузочный fingerprint защищает от незаметной смены идентичности;
подробнее — [запуск](usage.md).
