# Диагностика и восстановление

Начните с ошибки оболочки и последних загрузочных журналов экземпляра. Не
обходите неизвестную проблему отключением проверок или удалением flash.
Перед экспериментами сохраните остановленную копию; один диск нельзя запускать
двумя процессами одновременно.

## Веб интерфейс не открывается

Адрес по умолчанию — <http://127.0.0.1:5000/> на машине, где работает Pinology.
Для удалённого Linux-хоста пробросьте loopback-порт через SSH:

```sh
ssh -N -L 5000:127.0.0.1:5000 user@pi-host
```

Оставьте SSH-соединение открытым и зайдите по этому адресу со своего компьютера.
Если локальный порт занят, используйте `-L 15514:127.0.0.1:5000` и откройте порт
15514. Не решайте проблему туннеля публикацией DSM в интернет.

Проверка API различает запуск, готовность и недоступность; она не проверяет все
службы DSM. При первой установке используйте мастер в браузере и смотрите ход
загрузки. `NETWORK=N` намеренно исключает проверку API и сетевое выключение.
Прежде чем менять DNS или firewall, проверьте порты и выбранный экземпляр.

## Не работает HVF или KVM

На Apple Silicon используйте нативную сборку и проверьте разрешение hypervisor
в её подписи. Docker на macOS — не нативный путь HVF. На Linux проверьте ARM64,
наличие `/dev/kvm` и доступ контейнера к нему. KVM задаётся явно; при ошибке
оболочка не переходит на TCG автоматически.

Для этого KVM-пути CM4/Pi 4 нужен экспериментальный GICv2. Это не делает Pi 5
проверенной платформой. Не заменяйте ядро хоста и не включайте privileged Docker
ради обхода ошибки — выясните, какой именно возможности не хватает.

## Не проходит проверка памяти или диска

Гостю нужны 2 ГиБ плюс память эмулятора и хоста. Linux проверяет доступную RAM и
ограничения cgroup v2, когда они есть. При отсутствующем контроллере памяти Docker
не может обеспечить заданный лимит; `0B/0B` не означает нулевое потребление гостя.
macOS проверяет физический объём, а не гарантирует свободную память под нагрузкой.
Не отключайте проверки, не оценив остальные процессы.

Создание требует нового каталога экземпляра и нового соседнего кеша установочных
файлов. Прерванная попытка сохраняется для диагностики; повторяйте с новым именем,
а не удаляйте файлы вслепую. Несовпадение хеша означает неверную, неполную или
неожиданную прошивку. Проверьте модель и источник; не заменяйте закреплённые хеши
только ради прохождения проверки. qcow2 с backing file, физические диски хоста
и подмена файлов символьными ссылками не поддерживаются.

## DSM не вернулась после обновления

Проверьте, не появился ли во flash неразрешённый загрузочный профиль. Оболочка
намеренно отказывается от неизвестной прошивки вместо запуска старого кешированного
ядра с обновлённой системой. Одного совпадения ядра недостаточно: проверяются
initrd, DTB, модель и идентичность.

Восстанавливайтесь копированием проверенного **холодного checkpoint в новый
каталог**, затем запускайте копию. Неудачный экземпляр оставьте для диагностики.
Не перезаписывайте работающий экземпляр и не подключайте диск двум VM. Локальная
copy-on-write копия не является независимым бэкапом при отказе диска хоста.

## Выключение не завершилось вовремя

Предпочтительно выключать DSM из её интерфейса и ждать выхода оболочки/контейнера.
Для выключения через API нужны доступная сеть и приватный файл данных администратора.
При ошибке оболочка не обрывает питание. Собственный тайм-аут Docker всё же может
привести к SIGKILL: остановка контейнера не является безопасной заменой.
Закрытие терминала тоже не выключает гостевую систему штатно.

## Ошибки пакетов или датчиков

Проверяйте отдельные службы, а не только страницу входа. NPU, физические показания
потребления и часть периферии недоступны. Поддержка серийного номера лишь передаёт
указанную пользователем идентичность штатному ядру; она не гарантирует Photos,
push-уведомления и регистрацию в облаке. Не маскируйте неисправные службы, чтобы
представить частичный результат как полностью исправный.

## Сообщение о проблеме

Укажите ОС/архитектуру хоста, ускоритель, модель, ревизию исходников, результат
сборки, команду без секретов и короткий относящийся к проблеме фрагмент ошибки.
Уточните, это чистая установка или обновление, воспроизводится ли ошибка на
независимой копии. Не публикуйте PAT, диски/flash, пароли, аккаунты, реальные
серийные номера и непроверенные полные журналы. Даже штатный загрузочный журнал
ядра может содержать заданный серийный номер.

Команды безопасного выключения и checkpoint — в [руководстве по запуску](usage.md),
границы имеющихся проверок — в [архитектуре](architecture.md).
